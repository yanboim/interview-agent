# 访问控制

## 角色

| 主体 | 能力 |
|---|---|
| 未认证 | 产品Shell、注册/登录和公开健康入口 |
| 产品用户 | 当前认证用户拥有的资料、会话、面试、画像和任务 |
| 管理员 | 独立登录后的用户角色、审计、运行和知识管理 |
| 运维身份 | 部署平台、Secret、数据库、备份和监控的受控操作 |
| 服务身份 | 应用/Worker访问必要依赖 |

## 规则

- 服务端Token身份是用户所有权唯一权威；
- 客户端 `user_id`、隐藏菜单或路由不能授权；
- 产品和管理员凭据在签发前检查角色并使用独立浏览器存储；
- 管理接口每次请求校验管理员角色；
- 服务API Key是部署层附加保护，不替代用户认证；
- 运维和数据库权限不通过产品RBAC授予。

## 评审

新增资源必须定义所有者、读写角色、管理员能力、删除和审计。测试至少包含匿名、
正确用户、另一用户、普通用户调用管理接口和管理员成功场景。
