# Qdrant版本化知识发布

## 上下文

原导入流程在上传替代集合前删除 `QDRANT_COLLECTION`，并在上传后才运行质量评估。
上传或回归失败会删除最后一个已知良好知识库。

## 决策

使用不可变版本化物理集合和稳定服务别名：

```text
遗留回退：interview_knowledge
服务别名：interview_knowledge_current
版本：    interview_knowledge__v_<UTC时间戳>_<任务后缀>
```

读取方在每次逻辑检索/缓存查找时解析别名。别名尚不存在时使用遗留集合。发布创建并
验证版本，再通过一次Qdrant别名更新请求原子替换别名。

Redis保存带Token所有权和有界TTL的发布锁。释放使用compare-and-delete，过期发布者
不能释放新发布者的锁。

缓存Key包含别名背后的物理集合名。别名切换会改变缓存命名空间，无需扫描或删除无关
Redis Key。

## 失败行为

- 凭据失败：不创建集合。
- 上传或结构验证失败：只删除新候选。
- 回归失败：只删除新候选。
- 别名切换失败：只删除未发布候选；Qdrant原子应用别名操作列表，因此旧别名仍权威。
- 锁竞争：以冲突类错误拒绝发布。
- 已配置Redis但不可用：拒绝发布，不允许两个发布者。
- 未配置Redis：进程本地锁只支持本地开发。

## 回滚

回滚只接受名称符合配置版本前缀的现有集合，并原子把服务别名指向它。回滚绝不删除
离开的版本。

## 后果

- 实现保留策略前，历史版本持续占用Qdrant存储。
- 别名解析会在缓存查找前增加轻量Qdrant元数据请求；正确缓存版本优先于过早缓存别名。
- 别名改变后，各进程解析到的物理目标自然变化，无需广播进程内向量Store缓存失效。
