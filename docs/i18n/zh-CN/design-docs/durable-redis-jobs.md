# 持久Redis任务

## 决策

使用Redis原语实现一个小型可靠队列：

```text
ready列表
  -> 原子领取
processing租约ZSET
  -> 确认 -> completed Hash
  -> 失败 -> 延迟重试ZSET -> ready列表
  -> 达到最大尝试 -> 死信列表
  -> 租约过期 -> ready列表或死信列表
```

每个任务有唯一Hash，保存载荷、状态、尝试次数、最大次数、领取Token、租约截止、结果
和错误。Lua脚本使生命周期转换原子化。领取Token会阻止已不拥有租约的Worker执行确认、
失败或心跳。

入队在同一Lua事务中保存幂等键映射和任务。以相同任务请求复用Key会返回原任务ID；
不同请求复用则冲突。

Worker在知识导入期间续租。失败使用指数延迟。每次领取前运行Reaper以恢复过期租约并
提升到期重试。Worker反复崩溃最终会耗尽尝试次数并进入死信。

## 运维影响

- Worker可水平扩展，不依赖进程锁。
- 任务Hash是面向运维的事实来源。
- 在有审计的运维流程建立前，DLQ重放有意保持手工操作。
- 从旧JSON值ready列表部署时，需要排空或清理旧开发队列。
