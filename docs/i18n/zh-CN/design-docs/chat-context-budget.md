# 聊天上下文预算与持久摘要

## 边界

完成消息在 `messages` 中保持不可变。模型上下文是派生视图，包含：

1. 旧完成消息的有界系统摘要；
2. 能放入预算的最新完成消息；
3. 当前用户请求。

`app/chat_context.py` 负责纯规划和估算规则；
`ConversationStore.begin_chat_turn` 负责事务加载和持久化。

## 持久化

每个会话保存：

- `chat_summary`：有界确定性摘要文本；
- `chat_summary_through_message_id`：已纳入摘要的最大消息ID。

下一次压缩只考虑游标之后的消息。推进游标和领取回合位于同一事务，因此重试不会重复
摘要已覆盖消息。Pending输入和助手部分输出永不进入摘要。

## 预算行为

估算器使用UTF-8字节长度加固定消息封装开销，刻意保持保守且不依赖提供方Tokenizer。
完整历史能放入时原样传递；否则规划器预留有界摘要额度、保留可容纳的最新消息，并把
较旧前缀折叠进持久摘要。

当前请求始终保留。请求自身无法放入时，在持久领取回合前拒绝。
