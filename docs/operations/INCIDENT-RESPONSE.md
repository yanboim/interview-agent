# 事故响应

## 分级

| 级别 | 示例 | 响应 |
|---|---|---|
| SEV-1 | 跨用户泄露、数据破坏、全站不可用、秘密泄露 | 立即停止变更，建立指挥与沟通 |
| SEV-2 | 核心训练大面积失败、持续高错误、任务/知识发布阻断 | 快速缓解并持续观察 |
| SEV-3 | 局部功能降级、单一依赖波动、无数据风险缺陷 | 正常工作时段处理 |

## 首次响应

1. 确认影响范围、开始时间和最近变更。
2. 指定事故指挥、技术调查和沟通责任。
3. 保全日志、指标、Trace、版本和数据计数。
4. 停止发布、知识切换或其他可能扩大影响的操作。
5. 使用最小可逆方式缓解：隔离流量、关闭可选功能、回滚应用或知识别名。
6. 持续记录时间线、假设、操作和结果。

## 调查顺序

```text
用户症状
 -> app health/readiness
 -> request and dependency metrics
 -> app/worker logs and traces
 -> PostgreSQL / Redis / Qdrant
 -> model / embedding / search provider
 -> recent deploy, migration, config or knowledge version
```

## 安全事件

如涉及越权、秘密或私人数据：

- 限制访问并保留证据；
- 轮换受影响Secret、撤销会话；
- 不把敏感证据粘贴到公开Issue；
- 由授权负责人判断通知和合规义务。

## 恢复与关闭

恢复需要健康、核心流程、数据一致性和指标稳定证据。关闭后完成无责复盘：

- 影响和时间线；
- 检测、响应和恢复为何成功或失败；
- 根因和促成条件；
- 有负责人和截止时间的纠正措施；
- 测试、门禁、架构或运行手册更新。
