# 性能测试

## 目标

建立基线并发现退化，不在未测量前承诺固定SLA。重点覆盖HTTP、流式首包、数据库、
Redis、Qdrant和模型并发。

## 场景

- 健康/就绪和只读列表；
- 多用户并发创建聊天；
- 单会话并发冲突和安全重试；
- 面试答案提交及重放；
- 历史长会话的上下文摘要；
- RAG混合检索和重排；
- 知识导入、任务重试和别名切换。

## 指标

吞吐量、P50/P95/P99、首个流式事件、完整时长、错误率、冲突率、数据库连接、
Redis延迟、Qdrant延迟、模型并发/Token和资源使用。

## 数据与环境

使用合成用户和非生产知识，在生产等价但隔离环境运行。模型压测必须有成本上限；
多数协议和应用性能使用可控替身，Live测试单独批准。

## 判定

先保存版本化基线，再为关键场景批准预算。任何阈值调整记录原因；不能删除慢场景
或降低负载来隐藏退化。
