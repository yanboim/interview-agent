# 质量门禁

## 迭代门禁

- 聚焦单元和契约测试通过；
- 新行为具有失败和权限负向测试；
- 文档与功能契约同步；
- 不提交秘密、生成缓存或生产数据。

## 合并门禁

```bash
make harness-check
```

覆盖：

- 文档、功能契约和架构规则；
- Python编译和后端测试；
- 前端类型、单元、生产构建和Bundle预算；
- Playwright关键旅程。

CI还执行Python/npm依赖审计、容器构建和高危/严重镜像漏洞扫描。

## 数据库门禁

- 从空库升级到Head；
- 从支持的历史Revision升级并验证数据回填；
- 适用时使用PostgreSQL集成测试；
- 发布前备份、目标Revision和回滚限制明确。

## AI/RAG门禁

模型、Prompt、路由、知识、Embedding、分块或重排变化运行受影响评估。报告包含数据
集版本、配置、总体和分组指标。阈值调整必须解释原因，不能为了通过而静默降低。

## 发布门禁

- 制品从通过验证的源码构建并带校验和；
- 环境配置和秘密完整；
- Migration、备份和回滚计划评审；
- Canary健康、就绪、核心业务和错误指标通过；
- 生产扩大流量需要环境审批。

## 阻断规则

以下情况不得宣告完成或发布：

- 要求门禁未运行且没有批准的例外；
- 功能契约声称 `passing` 但没有真实证据；
- 已知跨用户越权、秘密泄露或数据破坏风险；
- 迁移无法验证或恢复目标不明确；
- Live评估可能把未获批私人数据发送给外部服务。
