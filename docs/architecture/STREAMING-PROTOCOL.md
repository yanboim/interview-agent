# 聊天流式协议

## 传输

前端通过 `POST /api/chat/stream` 接收NDJSON。每一行是一个完整JSON事件；客户端
必须按行解析，不能假设一个网络Chunk恰好对应一个事件。

## 事件语义

实现中的具体字段以路由和前端API类型为准，协议至少区分：

- 文本增量：追加到当前未完成回答；
- 来源：替换或合并结构化来源列表；
- 完成：回答成为正式持久结果；
- 错误：本次生成失败，不把片段视为正式回答；
- 取消：客户端停止读取，服务端记录取消状态。

## 顺序规则

```text
zero or more text events
  -> optional sources
  -> exactly one terminal outcome: completed, failed, or cancelled
```

完成响应可被相同幂等键重放。客户端应按事件类型处理未知扩展字段，并对无法解析的
行给出安全错误，而不是展示原始协议内容。

## 连接与重试

- 每次逻辑发送生成一个幂等键；
- 连接中断且结果不明确时，使用相同键和完全相同正文重试；
- 已完成请求由服务端重放，不再次调用模型；
- 生成中的请求返回冲突，客户端遵守 `Retry-After`；
- 用户修改正文后必须生成新键；
- 用户点击停止后可保留原键用于同内容从头重试。

## 持久化

增量片段只是传输状态。只有完成时，用户消息和助手消息才一起写入正式历史。
失败或取消状态保留在 `chat_turns` 用于诊断和重试，但不伪装成完成消息。
