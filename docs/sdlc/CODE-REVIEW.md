# 代码评审清单

## 意图与范围

- 变更是否解决PRD或问题描述中的目标？
- 是否存在未说明的范围扩张或无关清理？
- 当前行为、迁移路径和回滚是否清楚？

## 架构

- API是否只负责传输、身份和序列化？
- 业务编排是否在应用服务，纯策略是否保持基础设施无关？
- 是否出现反向导入组合根、重复客户端构造或新的全局状态？
- 外部调用是否在数据库事务外？

## 数据与并发

- 所有用户数据访问是否使用服务端身份过滤？
- 可重试写是否有幂等键、内容摘要、唯一约束或条件更新？
- 并发请求是否可能重复计费、重复推进或覆盖更新？
- Migration是否可从空库和历史状态升级？

## 安全与隐私

- 是否扩大攻击面、权限、网络暴露或外部数据流？
- 日志、指标和错误是否可能泄露Token、用户正文或私人知识？
- 管理员和产品用户的界面隔离是否仍有服务端校验？
- 危险操作是否要求明确目标和确认？

## AI与RAG

- Prompt、工具、模型或结构化输出变化是否有评估？
- 更换Embedding、分块或重排后是否重建并回归知识索引？
- 来源和拒答行为是否保持？
- 预算、超时、重试和成本是否在Gateway策略内？

## 前端与体验

- 服务端是否仍是业务事实来源？
- 加载、空、错误、冲突、取消和权限状态是否覆盖？
- 键盘、焦点、对比度和移动端是否可用？
- 重试是否保留命令身份和用户输入？

## 证据

- 测试是否会在实现错误时真正失败？
- 功能契约引用是否对应所声称行为？
- 文档链接、命令和版本是否正确？
- 是否记录未运行检查与残余风险？
