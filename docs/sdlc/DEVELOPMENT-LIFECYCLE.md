# 系统开发生命周期

## 1. 发现与立项

输入：用户问题、指标、事故、技术债或产品机会。

输出：

- 问题陈述和受影响用户；
- 成功指标和非目标；
- 风险、依赖和数据影响；
- 产品负责人对优先级的确认。

## 2. 需求与原型

更新PRD、用户故事、业务规则、用户流程、页面原型、异常状态和非功能需求。每个
需求拥有可观察的验收条件，并能够映射到功能契约或明确规划缺口。

门禁：[准备定义](DEFINITION-OF-READY.md)。

## 3. 架构与计划

确认：

- 模块、领域和数据所有权；
- 事务、幂等和并发边界；
- 外部数据流、权限和威胁；
- 迁移、发布、回滚和可观测性。

持久决定进入设计文档，实施步骤进入活动执行计划。小改动可以省略正式设计文档，
但不能省略正确性判断。

## 4. 实现

按最小垂直切片开发：

```text
contract -> domain/application -> adapter/storage -> UI -> evidence/docs
```

聚焦测试随实现一起添加。避免一次性横跨多个无关领域或进行旗标式大重构。

## 5. 验证

依次执行：

1. 受影响模块的单元/契约测试；
2. 迁移、集成或浏览器测试；
3. 安全、可访问性、AI评估或性能专项；
4. 适用的仓库质量门禁。

验证结果记录确切命令、通过/失败/跳过和外部依赖。

## 6. 评审

产品评审需求与原型，技术评审架构与正确性，代码评审实现、测试、数据和运行影响。
安全敏感或破坏性变化需要独立安全/运维确认。

## 7. 发布

构建不可变制品，完成备份与迁移检查，通过Canary或环境审批，验证健康、核心业务和
指标后再扩大流量。过程见[发布流程](../release/RELEASE-PROCESS.md)。

## 8. 运营与学习

观测错误、延迟、业务漏斗、模型和检索质量。事故进入响应和复盘；重复边界问题进入
技术债；新的产品发现回到第一步。

## 变更追踪

```text
Product need
 -> PRD / prototype
 -> feature contract
 -> architecture / design decision
 -> execution plan
 -> code + migration
 -> tests / evaluations
 -> release notes
 -> operational evidence
```
