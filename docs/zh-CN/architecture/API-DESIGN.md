# API设计规范

## 资源与身份

- HTTP路由按认证、聊天、会话、面试、画像/学习、资料和管理领域组织；
- 用户拥有的操作必须从认证上下文解析身份；
- 请求中的 `user_id` 不能作为授权依据；
- 管理端点统一位于 `/api/admin/*` 并校验管理员角色。

## 命令语义

- 安全可重试写操作使用 `Idempotency-Key` 或明确乐观并发条件；
- 幂等键需要稳定作用域、内容摘要、结果重放和冲突规则；
- 同键不同内容返回客户端错误；
- 命令正在执行时返回冲突，并在适用时提供 `Retry-After`；
- 主动重答等业务新尝试不复用网络重试的命令身份。

## 状态码

| 状态 | 使用场景 |
|---|---|
| `200/201/202` | 完成、创建或异步接受 |
| `400/422` | 语义或结构校验失败 |
| `401` | 缺少或失效认证 |
| `403` | 已认证但角色/所有权不允许 |
| `404` | 授权范围内资源不存在 |
| `409` | 幂等、并发或状态冲突 |
| `413` | 当前输入超过上下文/请求预算 |
| `429` | 限流 |
| `503` | 必要依赖未就绪 |

错误详情不得包含提供方原始错误、SQL、Token、秘密或私人知识。

## 查询与响应

- 列表接口按所有者过滤，稳定排序；
- 大列表逐步引入分页，不使用无界全表响应；
- 时间使用带时区ISO 8601；
- 结构化来源区分私人文件和公开URL；
- OpenAPI由FastAPI路由和Pydantic模型生成，是字段级参考来源。

## 兼容性

当前API未发布独立版本前缀。破坏性变化必须先记录设计、迁移客户端并在发布说明中
明确；未来公开或多客户端使用前应引入版本策略。
