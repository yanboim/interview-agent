# 容量规划

## 维度

- PostgreSQL：用户、消息、回合、事件增长，连接和索引；
- Redis：任务、租约、缓存、限流和持久化；
- Qdrant：分块数、向量维度、Sparse数据、历史版本；
- 用户文件卷：头像、简历原件、失败重试音频、增长和孤儿文件；
- 模型：并发、输入/输出Token、延迟、额度和成本；
- 转写：音频时长/大小、并发、超时、供应商配额和成本；
- 应用：线程执行器、内存、流式连接和静态资源；
- 观测：指标基数、日志量、Trace采样和保留。

## 流程

1. 记录当前用量和增长率。
2. 定义正常、峰值和故障重试场景。
3. 使用性能测试验证瓶颈。
4. 设置容量预警和扩容提前量。
5. 每次模型、知识规模或保留策略变化后复算。

## 保护

使用输入/输出预算、模型/转写并发、文件大小、限流、检索K、任务最大尝试和版本保留
控制资源。简历与长逐字稿采用有界批次和超时，避免单个任务长期占用Worker。删除
数据、用户文件或历史集合不是即时扩容手段，必须遵守保留、备份和回滚策略。
