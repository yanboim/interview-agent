# 用户敏感文件与异步处理

- 状态：Accepted / Implemented
- 日期：2026-07-28
- 负责人：后端、平台和安全负责人
- 关联产品规格：
  [简历驱动的面试训练与面试复盘](../product/RESUME-INTERVIEW-REVIEW.md)

## Context

系统已提供头像、简历和真实面试输入。管理员知识文件使用独立权限和用途，不能复用
为用户简历或面试音频存储。这些能力引入 Confidential 级别文件、长时间模型调用、
可选外部转写和跨进程 Worker 访问。

## Decision

### 文件存储

定义应用层文件存储接口，业务代码只使用资源 ID 和存储键：

```text
save(owner_id, asset_id, stream, metadata) -> StoredAsset
open(owner_id, storage_key) -> binary stream
delete(owner_id, storage_key) -> deleted/not-found
```

首版提供文件系统实现，根目录由 `USER_FILES_DIR` 配置。生产中的 API 和 Worker
挂载同一持久卷。
原始文件名只作为显示元数据；实际路径完全由服务端生成。文件不通过 StaticFiles
暴露，下载必须经过认证和所有权校验。

上传流程：

1. 认证并检查功能开关；
2. 流式写入临时文件，同时计算大小和 SHA-256；
3. 检查允许的扩展名、MIME、文件签名和大小；
4. 使用原子重命名提交；
5. 在数据库记录资源后再入队；
6. 任一步失败都清理未引用的临时文件。

生产环境要求底层卷和备份加密。首版不在应用层自行实现密钥和文件加密协议，
避免产生未经评审的密钥轮换和恢复机制。

### 后台任务

扩展现有 Worker 为显式处理器注册表：

```text
knowledge_import
resume_analysis
interview_transcription
interview_review_analysis
```

Redis 任务负载只包含资源 ID、命令 ID和安全枚举值。数据库保存业务状态、内容摘要、
处理所有者令牌、错误类别和结果。处理器先以条件更新领取资源，外部调用不位于
数据库事务内，完成时使用所有者令牌条件提交。

安全重试保证业务结果最多提交一次；进程在外部调用后、提交前崩溃时可能产生重复
供应商调用和成本，该限制必须通过指标和文档明确，不能宣称外部副作用 exactly-once。

### 生命周期与删除

- 简历原件保留到用户删除；
- 音频在逐字稿持久化成功后删除；
- 转写失败时保留音频以支持受控重试；
- 用户删除处理中资源时先标记删除，处理器在外部调用前和提交前检查；
- 删除最终清理数据库派生数据和文件；文件已不存在视为幂等成功；
- Redis 过期任务或迟到 Worker 不能重建已删除资源。

### 外部转写

定义 `TranscriptionProvider`：

```text
transcribe(path, language, diarize) -> TranscriptResult
```

结果统一为带开始时间、结束时间、文本和供应商说话人标签的片段。当前适配器使用
可配置的 Transcriptions API；业务层不暴露供应商原始响应。配置为空时音频入口返回
明确的功能不可用状态，文本逐字稿仍可处理。

调用要求超时、有限重试、并发预算、成本/用量指标和安全错误映射。日志、Trace 和
指标不得记录文件名、正文、供应商响应或用户标识高基数标签。

### 备份和恢复

备份清单扩展为 PostgreSQL、Qdrant 和用户文件卷。数据库与文件必须属于同一备份
批次并记录校验摘要。恢复演练验证记录引用的文件存在，但不得在未确认时覆盖生产卷。

## Alternatives

### 复用管理员知识文件目录

拒绝。管理员知识与用户材料的所有权、生命周期、索引和删除语义不同，会破坏权限
边界。

### 将二进制文件保存到数据库

首版拒绝。会放大数据库备份、事务和查询压力，也不利于后续切换对象存储。

### 首版直接使用对象存储

暂不采用。当前部署是单应用加共享 Worker，持久卷足以支持第一阶段；存储接口保留
后续 S3 兼容实现。规模化部署前必须重新评审。

### 转写后永久保留音频

拒绝。复盘以可编辑逐字稿为权威输入，持续保存音频增加敏感数据和备份负担。

## Consequences

- API 与 Worker 需要共享持久卷，备份范围扩大；
- 新文件能力必须增加内容嗅探、容量监控和孤儿文件检查；
- 删除横跨数据库、文件和队列，必须采用可重试的幂等清理；
- 云端转写引入新的供应商、成本和地区/保留审批；
- 将来切换对象存储时业务层接口和数据库资源 ID 保持稳定。

## Migration and rollout

1. 先部署数据库迁移和能够识别新任务类型的 Worker；
2. 验证共享卷、权限、备份和功能开关；
3. 再部署 API，简历、复盘和转写功能开关默认关闭；
4. 使用合成文件完成上传、处理、删除和恢复演练；
5. 分阶段启用简历，再启用文本复盘，最后启用云端音频转写。

## Verification

- 文件格式、大小、签名、路径穿越和跨用户负向测试；
- 数据库领取、所有者令牌、重试、删除竞争和迟到提交测试；
- 模拟供应商的超时、限流、无效响应和说话人分段测试；
- 音频删除顺序、孤儿文件清理、备份清单和恢复验证；
- 日志、任务载荷和指标不含正文的检查；
- `tests/test_resume_features.py`、`tests/test_interview_review_features.py`、
  `tests/test_user_files.py` 和迁移测试覆盖格式、所有权、状态与清理；
- `make harness-check` 是完整回归门禁。
