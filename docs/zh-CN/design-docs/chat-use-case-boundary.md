# 聊天用例边界

## 状态

本设计于2026年8月1日接受，用于定义RS-01的渐进式抽取边界；它本身不启用
Workflow V2。

## 背景

持久聊天回合生命周期已经由应用层拥有，但HTTP适配器仍负责路由选择、模型用途选择、
请求预算、Agent调用、工具证据提取、引用投影、Trace、完成、超时、失败和取消。
普通接口和流式接口因此重复了部分业务流程，并可能逐渐产生行为差异。

抽取必须保留当前正确性边界：

- 认证所有权由服务端解析；
- 使用幂等键和所有者令牌领取一个持久回合；
- 外部模型和网络调用位于数据库事务之外；
- 完成时原子写入最终消息和元数据；
- 超时、Provider失败和断开连接会安全释放会话；
- Workflow V2兄弟专家任务取消具有有界清理；不合作的Provider任务不能在父请求超时后继续
  占用持久回合锁；
- 已完成请求重放存储结果，不再次调用模型；
- 预算、证据隔离、确认、版本来源、指标和安全错误保持有效。

## 决策

引入一个由应用层拥有的聊天用例，协调完整逻辑回合。HTTP适配器只负责协议转换，
不再直接选择或调用Agent。

### HTTP适配器职责

- 校验HTTP Schema、Header、认证和授权；
- 将请求转换为 `ChatCommand`；
- 选择普通JSON或流式传输；
- 把应用事件和结果序列化为公开响应协议；
- 将稳定应用错误映射为HTTP状态和安全响应文本；
- 传播客户端断开产生的取消信号。

### 应用用例职责

- 领取或重放持久聊天回合；
- 构建服务端拥有的有界上下文快照；
- 通过注入策略选择允许的路由和模型用途；
- 建立并报告请求级执行预算；
- 在有界超时和取消语义下调用Agent执行端口；
- 标准化证据并生成引用元数据；
- 记录安全执行Trace以及产品和模型指标；
- 使用所有者令牌完成、失败或取消回合；
- 返回与传输协议无关的结果或生命周期事件。

### 端口

只在易变或具有副作用的边界使用小型端口：

- `ChatTurnRepository`：领取、重放、完成和终止状态转换；
- `ChatAgentExecutor`：执行准入后的Agent或模型；
- `ChatTraceRecorder`：记录安全的关联执行Trace；
- 只在确定性测试需要时注入时钟或标识符。

纯证据和引用转换仍是普通应用函数，不应仅为了增加接口数量而成为基础设施端口。

迁移期间，现有 `ConversationStore`、Agent组装和Trace持久化作为兼容适配器。
本设计不需要数据库迁移。

## 执行顺序

```text
HTTP适配器
  -> ChatUseCase.execute(command, cancellation)
       -> 领取或重放持久回合
       -> 建立身份和有界上下文
       -> 选择准入路由和预算
       -> 在数据库事务外调用ChatAgentExecutor
       -> 标准化证据和引用
       -> 完成持久回合并记录安全Trace
  <- ChatResult或稳定应用错误
```

流式变体使用相同的领取、执行策略、元数据和终止转换。它可以暴露传输无关的增量或
生命周期事件，但NDJSON/SSE格式仍属于HTTP适配器。客户端断开时请求取消，由用例
负责持久化 `cancelled` 状态。

## 错误语义

应用错误使用稳定类别，而不是原始Provider或数据库异常：

- 当前消息无效或超出预算；
- 幂等输入冲突；
- 回合正在执行或会话繁忙；
- 模型暂时不可用或执行预算耗尽；
- 执行超时；
- 客户端取消；
- 终止性内部失败。

原始异常文本只保留在安全的服务端日志和Trace中。HTTP适配器把类别映射为现有公开
响应行为。

## 工作流和检查点策略

RS-01是保持行为不变的边界抽取，继续使用当前准入Agent路径。显式Guard、Router、
Specialist、Verifier和Composer阶段属于RS-04。

普通聊天默认不增加持久LangGraph Checkpointer。持久聊天回合、所有者Fencing、规范
消息、元数据和安全Trace仍是产品状态。后续工作流只有在定义模型调用重放、旧所有者
Fencing、副作用幂等、隐私和保留语义后，才可以增加额外检查点。

## 被否决的替代方案

### 在两个Router中保留编排

普通和流式行为可能漂移，并且传输代码继续拥有模型和持久化策略，因此否决。

### 原样把Router主体移动到一个大型Service

这会把HTTP对象和响应格式隐藏到应用层，而不是建立传输无关的用例，因此否决。

### 在同一变更中引入Workflow V2

抽取和行为替换同时进行会失去可信比较边界并增加回滚难度，因此否决。

### 立即持久化每个Agent节点

外部模型调用不具备Exactly-once语义；没有明确Fencing和副作用语义时自动接管并不
安全，因此否决。

## 迁移

1. 增加Command、Result、Error契约和兼容执行适配器。
2. 在不改变行为的情况下把非流式接口迁入用例。
3. 把流式执行迁入同一用例和共享终止处理。
4. 增加架构断言，禁止API Router调用Agent或模型。
5. 聚焦门禁和仓库门禁通过后移除兼容编排。

每一步都可独立回滚，并且不需要Schema迁移。

## 验证

- 聊天生命周期、重放、超时、预算、Provider失败和取消；
- 普通与流式元数据和引用一致性；
- 跨用户和幂等负向场景；
- 模型调用仍位于Repository事务之外；
- 禁止API Router调用Agent或模型的架构规则；
- 确定性Agent质量和模型路由不回退；
- RS-01完成前通过 `make harness-check`。
