# 架构

## 目的

Interview Agent是一个模块化单体，为Vue Web应用提供FastAPI API。系统组合认证用户
数据、面试流程、学习计划、基于LLM的教练和私人Qdrant知识库。

当前部署单元有意保持为一个应用加一个后台Worker。在单体内部事务和模块边界明确前，
不以拆分网络微服务为目标。

## 运行上下文

```text
浏览器
  |
  v
FastAPI API / 静态前端
  |---- PostgreSQL或SQLite：用户、会话、简历、复盘、学习、审计
  |---- Redis：共享限流、RAG缓存、后台任务
  |---- Qdrant：版本化私人知识索引
  |---- 用户文件卷：头像、简历、临时复盘音频
  |---- GLM API：聊天、面试问题、评分、可选重排
  |---- 转写API：可选且需用户同意的音频转写
  `---- Worker：知识、简历、转写和复盘任务
```

Prometheus、Grafana和OpenTelemetry负责观测应用，但不属于请求正确性边界。

## 逻辑分层

目标依赖方向：

```text
API适配器
    -> 应用服务
        -> 领域策略与计算
            <- 基础设施实现
```

### API适配器

负责HTTP校验、认证依赖、状态码和响应序列化。不负责面试状态转换、Prompt构造、SQL
查询或重试策略。

当前位置：

```text
app/api/runtime.py
app/api/schemas.py
app/api/security.py
app/api/routers/
```

`app/main.py` 是组合根：构建依赖、安装中间件和静态路由、注册领域路由。

### 应用服务

协调一个用例及其事务/并发边界，例如提交面试答案或生成聊天回合。应用服务依赖仓储
和模型接口，而不是全局客户端。

当前应用服务：

```text
app/application/chat_service.py
app/application/interview_service.py
app/application/resume_service.py
app/application/interview_review_service.py
```

新的复杂行为应继续移向此边界，不能放入API路由或 `app/main.py`。

知识发布当前由导入/Worker适配器和 `app/knowledge_publication.py` 协调。只有新增API
用例确实需要面向应用的边界时，才引入
`app/application/knowledge_service.py`；当前没有该文件。

### 领域策略

包含确定性计算和状态转换规则，必须独立于FastAPI、SQLAlchemy、Redis、Qdrant、
HTTP客户端和LLM SDK。

当前示例包括 `app/learning.py`、`app/chunks.py` 和 `app/evaluation.py`。架构测试会
强制它们保持纯净。

### 基础设施

负责SQLAlchemy、Redis、Qdrant、外部HTTP、遥测和模型提供方细节。基础设施可以实现
应用层接口，但不能导入API组合根。

当前实现仍按扁平模块组织在 `app/` 下。逐步移动到 `app/infrastructure/`，不进行
一次性重写。

## 正确性边界

### 用户数据

服务端解析的认证身份是权威。所有用户资源查询和变更都包含 `user_id`；客户端传入
的ID永远不足以授权。

管理员可观测性有三个不同的持久化关注点：

- `audit_events` 记录谁执行API动作、经清理的目标、请求ID、结果和耗时；
- 权威聊天/面试表仍是精确用户输入和系统输出的唯一来源；
- `execution_traces` 和关联工具审计记录模型/工具阶段以及安全元数据，不复制Prompt、
  凭据或私人知识正文。

管理员跨用户读取交互内容的行为本身也会被请求审计记录。

### 数据库写入

一个业务状态转换应原子提交。可重试命令需要幂等键或乐观并发条件。Python进程锁
不是多实例部署中的正确性机制。

持久化使用同步SQLAlchemy Core。API适配器通过共享 `SyncExecutor` 分派阻塞用例，
不能分别调用 `asyncio.to_thread`。`ConversationStore` 变更是事务脚本，拥有一个
`engine.begin()` 边界；读取拥有一个 `engine.connect()` 边界。外部模型和网络调用
绝不位于这些数据库事务中。

业务并发由条件更新、唯一约束、外键、幂等键和所有者Token保证。Store唯一的本地锁
只保护可选Schema初始化，不参与业务正确性。

### 聊天与面试回合

每个逻辑回合具有持久身份和显式生命周期：

```text
pending -> generating -> completed
                    `-> failed或cancelled
```

首个面试答案和聊天提交通过持久回合ID、客户端幂等键、数据库条件领取、领取所有者
Token和存储响应重放实现该生命周期。

聊天还会按会话串行化生成，并只在完成后一起物化用户和助手历史消息。提供方失败或
流式取消会释放会话，并保留failed/cancelled回合供重试。如果进程在 `generating`
时崩溃，仍需显式运维恢复；在模型调用围栏能阻止旧慢所有者恢复前，禁止自动租约接管。

### 知识发布

知识导入是发布过程：

```text
构建版本化集合
  -> 验证结构
  -> 运行回归门禁
  -> 原子切换别名
  -> 失效版本化缓存
  -> 保留上一版本用于回滚
```

实现使用版本化物理集合、候选验证、原子切换服务别名、按物理目标版本化缓存Key并保留
上一版本。验证前删除服务集合始终禁止。

### 用户敏感文件与长时间分析

头像、简历和临时面试音频使用服务端生成存储键和认证下载路径；用户文件绝不作为静态
资源提供，也不放入Qdrant。API和Worker共享配置的持久用户文件卷。数据库记录是所有权
和生命周期权威，文件清理保持幂等。

简历分析和面试复盘采用显式持久资源状态、带所有者围栏的后台任务、有界模型/转写
调用，以及优化稿和逐字稿的乐观版本。只有启用转写且用户明确确认外部处理，音频才会
离开系统。逐字稿成功持久化后删除音频。

### 模型调用

提供方调用必须具有有界超时/重试、指标、安全错误映射和Token/成本核算。Prompt和
结构化输出Schema属于版本化行为。提供方支持结构化输出时，产品代码不能依赖未校验的
自由JSON。

`app/model_gateway.py` 是外部聊天/Embedding的唯一构建入口。它执行超时、重试、并发、
输入/输出预算、安全错误、延迟/错误指标和Token核算策略。Agent图和应用服务负责Prompt
及编排，提供方传输不负责业务编排。

聊天模型输入是有界派生视图；`messages` 始终是不可变历史事实来源。
`app/chat_context.py` 规划与提供方无关的窗口，包括持久摘要、近期已完成消息和当前
请求。会话摘要游标与聊天回合领取在同一事务内推进，因此失败/重试调用不会重复压缩。

`app/agent_context_service.py` 负责独立且不可变的逐回合Agent上下文快照。它把服务端
解析的身份和画像数据，与已确认且限定所有者的教练记忆、当前能力弱项、到期学习任务
和有界会话视图组合起来。待确认、已拒绝或来源过期的派生记忆绝不会进入快照。专业
Agent调用接收一个版本化 `DelegationEnvelope`，其中包含紧凑快照和关联ID；系统不会
为每次委派复制完整聊天记录。记忆生命周期操作仍是显式产品/API命令；记忆被纠正后会
回到 `proposed` 状态，直到所有者再次确认。

持久多步骤Agent操作使用 `app/application/agent_run_service.py`，并把应用拥有的
`agent_runs`/`agent_steps` 记录作为业务事实来源。稳定输入摘要与步骤幂等键把重试绑定
到原始命令。步骤领取使用条件更新并受所有者围栏保护；命令副作用、重放结果和步骤/
运行终态原子提交，未来的模型或工具调用则保持在数据库事务之外。SSE只暴露生命周期
事件，管理员检查会省略用户拥有的输入、提案与结果正文。LangGraph仍是进程内编排细节，
不作为持久产品状态。

## 部署与生命周期

- Alembic负责生产Schema演进；运行时 `create_all` 只用于本地和隔离测试。
- 应用接收流量前完成迁移。
- `/health` 表示存活；`/ready` 验证必要依赖。
- Worker使用带所有者围栏的Redis领取、任务租约心跳、确认、有界重试、崩溃恢复和终态
  失败。独立进程心跳使用有界Redis TTL，在空闲或处理时持续更新，为管理员资源中心
  提供实时Worker信号。
- 启用简历或复盘处理的API和Worker部署必须挂载同一持久用户文件卷。备份恢复把关系
  记录与该卷作为同一恢复集。
- 经验证的Canary和生产结果由运维侧部署流程写入幂等发布台账。Git历史不能证明版本
  已到达环境；产品用户不能访问该管理员读取模型。
- Compose是开发参考环境。每个Worktree派生稳定 `COMPOSE_PROJECT_NAME` 和宿主端口
  块；Compose项目名隔离容器、网络和命名卷。
