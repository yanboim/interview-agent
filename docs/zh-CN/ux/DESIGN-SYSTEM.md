# 设计系统

## 基础原则

- 界面优先支持阅读、作答和恢复任务，不以装饰干扰训练。
- 状态不能仅靠颜色表达；文字、图标和结构共同传达语义。
- 组件优先复用 `frontend/src/components/ui/`，领域组件不重复实现基础按钮和状态。

## 视觉令牌

颜色、字体、间距、圆角、阴影和断点应通过CSS变量或共享样式定义，而不是散落魔法
值。主题至少覆盖背景、表面、主文字、次文字、边框、主操作、成功、警告和错误。

## 组件

| 组件 | 规则 |
|---|---|
| 按钮 | 主操作每个区域最多一个；加载时保持尺寸；危险操作明确标记 |
| 表单 | 标签常驻；错误靠近字段；提交失败不清空输入 |
| 状态 | 使用统一加载、空、错误和权限状态组件 |
| 对话框 | 键盘陷阱、Escape、初始焦点和恢复焦点 |
| Toast | 只承载短反馈，不承载必须阅读的恢复步骤 |
| 来源卡 | 区分私人文件和公开URL，展示可理解来源信息 |
| 评分 | 展示维度、范围和解释，不只展示总分 |

## 响应式

- 桌面使用侧栏和主面板；
- 小屏导航折叠，主任务保持单列；
- 触控目标足够大，输入和按钮不产生横向溢出；
- 表格在小屏转为卡片或受控滚动，不压缩为不可读文字。

实现变化应通过截图/浏览器验收和可访问性检查，而不是只审查CSS。
