# 访问控制

## 角色

| 主体 | 能力 |
|---|---|
| 未认证 | 产品Shell、注册/登录和公开健康入口 |
| 产品用户 | 当前认证用户拥有的资料、头像、会话、面试、简历、复盘、画像、任务、训练记忆、反馈和Agent运行 |
| 管理员 | 独立登录后的用户角色、资源、审计、交互检查、发布记录和知识管理 |
| 运维身份 | 部署平台、Secret、数据库、备份和监控的受控操作 |
| 服务身份 | 应用/Worker访问必要依赖 |

## 规则

- 服务端Token身份是用户所有权唯一权威；
- 客户端 `user_id`、隐藏菜单或路由不能授权；
- 产品和管理员凭据在签发前检查角色并使用独立浏览器存储；
- 管理接口每次请求校验管理员角色；
- 管理员读取跨用户权威交互内容必须经专用接口并产生审计事件；
- 训练记忆、回合反馈、动作确认和Agent运行的每次读写都使用服务端解析的所有者；
- Agent变更和模糊外发确认绑定所有者、预览内容和有效期，不能由客户端替换目标；
- 管理员Agent运行视图仅用于恢复和诊断，不能读取用户正文或代替用户确认；
- 服务API Key是部署层附加保护，不替代用户认证；
- 运维和数据库权限不通过产品RBAC授予。

## 评审

新增资源必须定义所有者、读写角色、管理员能力、删除和审计。测试至少包含匿名、
正确用户、另一用户、普通用户调用管理接口和管理员成功场景。
