# 简历驱动的面试训练与面试复盘

- 状态：已实现；音频入口仍受部署方供应商审批与配置控制
- 日期：2026-07-28
- 负责人：产品与研发负责人
- 关联功能：
  - `resume-assessment-and-optimization`
  - `resume-grounded-mock-interview`
  - `real-interview-transcription-review`

本文定义三个已交付阶段的产品目标和验收边界。当前行为和证据以
[功能契约](../product-specs/feature-contract.json)中对应 `passing` 条目为准。

## 1. 产品目标

把用户的求职准备材料和训练记录连接成持续闭环：

```text
简历/JD
  -> 简历评估与优化
  -> 基于简历的定向模拟面试
  -> 真实面试逐字稿与复盘
  -> 能力画像和学习任务
```

目标用户仍是技术岗位求职者。系统提供训练辅助和改进建议，不替代招聘方判断，
也不保证获得面试或录用结果。

## 2. 分阶段范围

### 阶段一：简历评估与优化

用户能够上传 PDF 或 DOCX 简历，选择或继承目标 JD，查看结构化评估，逐条采纳或
编辑改写建议，预览完整优化稿并导出 DOCX。

首版包括：

- PDF、DOCX，单文件默认不超过 10 MiB；
- 可提取文本的 PDF；扫描版 PDF 明确提示暂不支持 OCR；
- JD 优先、目标岗位与经验级别兜底；
- 岗位匹配、完整性、相关性、表达、成果量化和 ATS 可读性评估；
- 逐项问题、来源证据、修改建议和完整优化稿；
- 网页编辑、版本冲突提示和标准单栏 DOCX 导出；
- 简历列表、分析版本、失败重试和删除。

首版不包括：

- OCR、图片简历、PDF 导出；
- 原文件视觉版式复刻；
- 自动投递、职位搜索或招聘流程管理；
- 编造用户未提供的公司、职位、日期、技术、数字或业绩。

### 阶段二：简历定向模拟面试

用户能够在开始现有文字模拟面试时选择一个已完成的简历分析版本。系统围绕简历
项目、技能、职责、成果和 JD 差距出题、追问和评分。

首版包括：

- 复用现有主题、难度、题数、逐题作答、评分、重答和报告；
- 项目深挖、技术真实性、职责边界、成果量化和岗位差距问题；
- 面试历史显示通用或简历定向来源；
- 分数继续进入能力画像和学习任务。

首版不包括语音作答、实时视频面试或人工面试官加入。

### 阶段三：面试复盘

用户能够上传面试音频或提交文本逐字稿。音频异步转写后，用户必须确认文本和
说话人角色，系统才生成结构化复盘。

首版包括：

- MP3、M4A、WAV、WebM，默认不超过 25 MiB；
- TXT、Markdown 或页面粘贴文本；
- 可配置云端转写服务和说话人分段；
- 用户修正、合并或拆分片段并确认候选人/面试官角色；
- 整体摘要、逐题问答、四维评分、亮点、遗漏点、改进回答和行动计划；
- 真实面试结果以独立来源进入能力画像和学习任务；
- 历史查看、失败重试和删除。

首版不包括视频上传、实时录音、情绪或表情识别、招聘录用预测。

## 3. 关键业务规则

### 3.1 身份和所有权

- 新资源只使用服务端认证身份确定所有者，不接受客户端提供的用户 ID 作为授权；
- 用户不能读取、修改、导出、触发处理或删除其他用户的资源；
- 后台任务负载只保存资源 ID，不保存简历、JD、音频或逐字稿正文。

### 3.2 简历事实保护

- 每条改写建议必须能追溯到原简历章节或文本证据；
- 模型不得新增原文没有的专有名词、任职时间、技术栈、数字或成果；
- 缺失信息使用“待补充”问题，不将假设写成事实；
- 存在未解决事实警告或占位符时禁止导出；
- 用户编辑和确认后的内容才是优化稿的权威版本。

### 3.3 JD 选择

评估基准按以下顺序确定，并在分析创建时保存快照：

1. 用户为本次分析提供的 JD；
2. 用户个人资料中的 JD；
3. 目标岗位、经验级别和关注方向。

之后修改个人资料不会改变历史报告。重新评估会创建新的分析版本。

### 3.4 转写与确认

- 音频上传前展示外部转写的数据范围并要求用户明确确认；
- 转写服务未配置或用户未确认时不得外发音频；
- 自动说话人标签只作为建议，用户确认最新逐字稿版本后才可评分；
- 修改已确认逐字稿会使旧确认失效，必须重新确认；
- 复盘只评价被标记为候选人的回答。

### 3.5 数据保留和删除

- 原始简历保留到用户主动删除；
- 音频在逐字稿成功持久化后删除；处理失败时仅为重试暂存；
- 逐字稿和复盘报告保留到用户删除复盘记录；
- 删除简历会删除原件和分析版本，但不会自动删除已产生的历史模拟面试；
- 历史面试只保留其自身问题、回答和最小化来源说明；
- 正式自动保留期限、账号级导出和账号删除仍需产品与法律审批。

## 4. 核心状态

### 简历分析

```text
uploaded -> parsing -> analyzing -> ready
                    \-> failed -> retrying
```

### 面试复盘

```text
uploaded -> transcribing -> awaiting_confirmation
                                  -> analyzing -> completed
             \-> failed                \-> failed
```

删除操作在任意非终态都可请求。后台处理器发现资源已删除时必须安全停止，不重新
创建资源。

## 5. 页面和交互

- `/resumes/:resumeId?`：上传、历史、报告、改写编辑、预览和导出；
- `/interviews/:interviewId?`：增加可选简历来源和来源标记；
- `/reviews/:reviewId?`：音频/文本输入、处理进度、逐字稿确认和复盘报告；
- `/profile`、`/learning`：区分模拟面试与真实面试来源。

所有页面覆盖加载、空、成功、失败、冲突、重试、删除和权限拒绝状态，并保持桌面
与移动端核心流程一致。

## 6. 成功标准

- 用户能从一份简历完成评估、编辑和 DOCX 导出，且报告不引入未确认事实；
- 简历定向面试的问题能够引用简历项目或岗位差距，而通用面试行为不回归；
- 音频成功转写后原文件被删除，逐字稿未经确认不能生成评分；
- 真实面试报告能形成可执行的学习任务，并与模拟面试数据区分；
- 三阶段均通过用户隔离、失败恢复、幂等/并发、隐私和可访问性验收。
