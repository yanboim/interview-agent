# 产品愿景

## 产品定位

Interview Agent 是面向技术岗位求职者的持续训练工作台。它把岗位目标、知识问答、
模拟面试、能力诊断和间隔复习串成一个有记录、可恢复、可度量的学习闭环。

它不是简历投递平台、招聘决策系统或通用聊天机器人，也不应将模型评分包装成对
候选人真实能力的权威认证。

## 核心问题

技术面试准备通常存在四个断点：

1. 学习资料、问答和模拟面试相互割裂。
2. 单次练习结束后缺少跨场次能力趋势。
3. 薄弱点没有转化为可执行且会再次出现的复习任务。
4. 生成式反馈缺乏来源、过程状态和失败后的恢复能力。

## 目标用户

- 正在准备技术岗位面试的求职者；
- 希望从一个技术方向转向另一个方向的工程师；
- 希望通过持续模拟和复习巩固知识的在职工程师；
- 负责维护私人知识库、运行状态和用户权限的系统管理员。

## 价值主张

- 围绕目标岗位组织训练，而不是提供无上下文的题库。
- 用可恢复的模拟面试和多维评分提供明确反馈。
- 将跨场次薄弱点转为学习任务和复习计划。
- 私人知识检索提供来源信息，模型和外部搜索保持可配置、可关闭。
- 对重试、并发和知识发布定义可靠性边界，避免重复计费或破坏服务版本。

## 产品原则

1. **用户数据权威在服务端。** 浏览器不决定资源所有权或业务完成状态。
2. **反馈必须可解释。** 来源、评分维度和薄弱点应能被用户理解。
3. **失败必须可恢复。** 网络、模型或依赖失败不应制造重复业务结果。
4. **私人数据默认不外发。** 外部模型、Embedding 和搜索的数据流必须显式。
5. **训练闭环优先于功能数量。** 新能力应改善“目标—训练—反馈—复习”之一。

## 成功标准

以下是产品应持续观测的指标方向，不代表当前已经批准具体目标值：

- 完成首次目标设置的注册用户比例；
- 从今日训练进入并完成一次训练的比例；
- 模拟面试完成率和中断后恢复率；
- 一周内再次训练或完成复习的用户比例；
- 用户查看带来源回答和面试报告的比例；
- 模型调用失败率、重复调用率和端到端延迟；
- RAG检索相关性、引用覆盖率和回答忠实度。

正式指标口径和目标值应在后续指标文档中审批，并与埋点和监控查询对应。

## 非目标

- 自动替代真实面试官或招聘录用判断；
- 未经人工确认自动修改用户简历或代替用户投递；
- 从公开网络无约束抓取或长期保存第三方内容；
- 用一次模型评分形成不可申诉的能力结论；
- 在缺少数据治理和租户边界的情况下提供组织级招聘产品。
