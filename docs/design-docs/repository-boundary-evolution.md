# 仓库边界演进决策

- 状态：已接受
- 日期：2026-08-01
- 适用计划：RS-00～RS-11

## 背景

当前模块化单体已经具备持久回合、幂等、模型网关、确认协议、版本化知识发布和
完整 Harness。主要风险不再是缺少基础能力，而是 HTTP 适配器、集中式持久化模块、
命令脚本和 Agent 编排之间的责任仍然过宽。演进必须保留现有产品契约和可回滚性，
不能以目录移动代替边界设计。

基线以 [结构演进基线](../../eval/reports/repository-structure-baseline-2026-08-01.json)
为准；其指标由已有确定性 Agent 报告和已批准路由报告机械校验。

## 决策一：完整 Chat Use Case 属于应用层

应用层拥有领取/重放、路由、预算、Agent 执行、证据投影、追踪、完成、失败、超时和
取消的协调。HTTP 适配器只拥有认证、Header/Schema 校验、HTTP/NDJSON 序列化和断连
信号。普通与流式入口使用同一个命令、执行端口和完成规则；外部模型调用始终位于
数据库事务之外。

应用接口采用显式的 `ChatCommand`、`ChatResult`、执行事件和窄端口。兼容迁移期间可
保留旧路由，但架构测试最终禁止路由直接选择模型或调用 Agent。

## 决策二：持久化按聚合端口逐片拆分

保留一个 SQLAlchemy Engine 和现有事务规则，不引入数据库拆分。应用服务依赖聊天、
面试、简历/复盘、学习/Agent Run、审计/管理等窄协议；实现可以暂时委托给
`ConversationStore`。只有完整聚合的调用方和测试迁移后，才移动实现并删除兼容方法。
跨表原子状态转换保持在同一事务脚本中。

## 决策三：Checkpoint 由业务恢复语义决定

普通聊天的权威状态是持久 chat turn，LangGraph 只是进程内执行细节，不额外引入
checkpointer。可恢复多步骤动作的权威状态是 `agent_runs`/`agent_steps`，每一步具有稳定
输入摘要、幂等键、owner fencing 和原子终态。只有新工作流确实需要从内部图节点恢复，
并且能证明旧模型/工具调用不会迟到双写时，才允许增加图 checkpoint。

因此，静态扫描“使用 LangGraph 但没有 checkpointer”不是缺陷证明；必须检查业务状态
机和副作用 fencing。

## 决策四：知识种子与运行数据分离

`knowledge/` 是随源码版本化、经过批准的种子，默认仍按机密数据处理；只有明确标注并
经过发布审批的样例才可视为公开内容。`eval/` 是非生产评测夹具及报告。用户或运营方
运行期知识只能进入外部持久卷，不能提交源码或烘焙到公开镜像层。携带种子的发布镜像
也必须作为受控内部制品。版本化 Qdrant 集合是派生运行数据，可由种子/已批准输入重建；
关系库、用户文件卷和发布别名状态按运行手册备份。`.var/` 作为本地运行数据库、备份、
trace 和临时产物的推荐根目录，并保持忽略。

受控容器镜像可以携带获批种子；Compose 使用普通命名卷首次挂载时由 Docker 复制镜像
目录内容的语义初始化 `knowledge_data`，不得改为 `nocopy` 或空 bind mount 而无显式
初始化步骤。导入仍遵循候选集合构建、验证、评测、原子切换和保留回滚版本的流程。

## 当前责任清单

| 文件 | 当前责任 | 目标所有者 |
|---|---|---|
| `app/api/routers/chat.py` | HTTP、Chat 编排、Agent 调用、流式序列化 | HTTP 留在 API；编排移入应用层 |
| `app/storage.py` | 多聚合 SQL 与事务脚本 | 按聚合的窄 Repository 实现 |
| `app/tools.py` | 知识、公开搜索、学习动作与确认 | 按工具能力拆分，共享安全网关 |
| `app/operations.py` | 指标、限流、Redis Job、Heartbeat | 按运维能力拆分 |
| `scripts/ingest.py` | 知识导入实现与 CLI | 实现进运行时模块；脚本仅 CLI |
| `scripts/worker.py` | Worker 处理、租约循环与 CLI | 处理进运行时模块；脚本仅启动 |

## 被拒绝的方案

- 一次性拆成微服务：扩大事务、部署和恢复面，不解决内部职责问题。
- 只移动文件：不改变依赖方向，无法由测试证明边界。
- 为所有 LangGraph 调用强制 checkpoint：产生双重事实来源，且不能自动解决迟到副作用。
- 直接移动或删除本地/运行数据：缺少恢复证明，具有破坏性。

## 验证和回滚

每个切片必须运行聚焦测试并最终通过 `make harness-check`。结构基线测试验证关键质量、
完成率、延迟、成本和引用指标未被悄然替换。迁移期间兼容适配器提供逐片回滚；任何数据
位置变更必须另立包含备份、恢复和显式操作员确认的计划。
