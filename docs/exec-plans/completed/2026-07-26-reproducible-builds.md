# Reproducible dependencies and images

- Status: completed
- Date: 2026-07-26
- Owner: repository maintainers
- Technical debt: TD-010
- Product contract: `reproducible-build-inputs`

## Objective

Make production Python resolution and container inputs reviewable and
repeatable by committing a hash-verified transitive lock and immutable image
manifest digests, with CI-enforced drift checks.

## Non-goals

- Guarantee bit-for-bit identical Docker layer tarballs across builders.
- Automatically merge dependency updates.
- Change application behavior or model providers.
- Fold the frontend major-version upgrade from TD-011 into this task.

## Acceptance criteria

- Human-reviewed Python direct requirements live separately from the generated
  transitive lock.
- Every locked Python distribution is exactly pinned and hash verified.
- Docker and CI install only from the lock with `--require-hashes`.
- The lock records and CI verifies a digest of its direct-requirement input.
- Dockerfile base images and all external Compose images use version tags plus
  immutable multi-platform manifest digests.
- A repository verifier rejects ranges in the lock, missing hashes, `latest`,
  unpinned external images, and incorrect install commands.
- The documented update workflow regenerates, verifies, tests, and reviews
  dependency changes.
- `make harness-check` passes.

## Decisions

- `requirements.in` is the review surface; `requirements.txt` is generated by
  pip-tools for CPython 3.12 Linux with hashes.
- The lock carries the SHA-256 of `requirements.in`, allowing a fast offline
  drift check on every Harness run.
- Tags remain beside image digests for operator readability; digests determine
  the actual content.

## Findings

- The generated lock resolves 3.12-compatible versions that are slightly newer
  than the pre-existing developer environment; the clean-container suite
  proves those resolved versions are compatible.
- Qdrant is now fixed at `v1.15.1` plus its Linux/amd64 manifest digest instead
  of `latest`.
- The current immutable digest set intentionally targets Linux/amd64. Another
  production architecture requires a separately reviewed digest set.

## Rollback

The previous broad requirements can be restored from `requirements.in`.
Digest pins can be rolled back to the prior reviewed digest without changing
volumes or application data.
