## Objective

允许用户以音频或文本提交已经发生的真实面试，在确认逐字稿和说话人后生成逐题
复盘，并把明确标记为真实来源的评分连接到能力画像与学习任务。

## Non-goals

- 视频上传、实时录音、实时字幕或实时面试；
- 情绪、语气、外貌或表情识别；
- 自动招聘结论、录用概率或候选人排名；
- 未经确认直接将自动转写写入能力画像；
- 永久保存原始音频。

## Acceptance criteria

- 用户可以提交支持格式音频或文本，并查看可恢复的异步状态；
- 音频外发前明确告知供应商数据流并记录用户确认；
- 转写服务关闭时拒绝音频但保留文本入口；
- 自动逐字稿可编辑、合并、拆分和标记说话人；
- 修改逐字稿会使旧确认失效，只有最新确认版本能进入分析；
- 复盘只评价候选人回答，无法配对内容不强制评分；
- 报告、逐题评分和能力数据原子提交，不产生半完成结果；
- 逐字稿持久化成功后才删除音频，失败时可安全重试；
- 删除复盘记录清理逐字稿、报告、回合和残留音频；
- 跨用户、重试、并发、隐私、成本、可访问性和 Harness 验收通过。

## Public interfaces

```text
POST   /api/interview-reviews/audio
POST   /api/interview-reviews/text
GET    /api/interview-reviews
GET    /api/interview-reviews/{review_id}
PATCH  /api/interview-reviews/{review_id}/transcript
POST   /api/interview-reviews/{review_id}/confirm-and-analyze
POST   /api/interview-reviews/{review_id}/retry
DELETE /api/interview-reviews/{review_id}
```

音频创建和确认分析要求 `Idempotency-Key`。逐字稿编辑携带 `expected_revision`。
外部供应商确认作为音频创建的必填布尔值和审计时间保存。

先部署迁移和 Worker，默认关闭音频；先启用文本复盘，再以合成数据启用音频转写，
最后逐步开放用户入口。回滚先关闭音频和复盘开关，保留用户逐字稿和报告，不执行
破坏性降级或批量删除。

## Decisions and findings

- 首版使用供应商无关的 multipart HTTP 适配器，不把某一家供应商硬编码进领域层。
- 音频功能与文本复盘分开开关；转写未配置时文本入口不受影响。
- 供应商说话人标签始终降级为 `unknown`，用户确认最新版本后才能进入分析。
- 自动重试可重新领取失败任务；数据库提交成功前保留音频，成功后立即删除。
- 已完成复盘被编辑时旧报告和能力回合原子清理，要求用户重新确认。
