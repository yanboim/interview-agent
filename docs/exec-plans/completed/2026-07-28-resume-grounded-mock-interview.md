## Objective

让用户从一个已完成的简历分析版本开始文字模拟面试，问题围绕简历项目、技能、
职责、成果和目标 JD 差距，同时保持现有面试的幂等、恢复、评分和报告行为。

## Non-goals

- 语音、视频或实时面试；
- 修改简历或在面试过程中重新分析简历；
- 用完整简历正文替换现有面试历史；
- 改变现有通用模拟面试默认行为；
- 将简历定向评分解释为招聘结论。

## Acceptance criteria

- 用户只能选择自己状态为 `ready` 的简历分析；
- 不选择简历时现有通用面试的接口和结果保持兼容；
- 首题和后续题能基于稳定的最小上下文快照，不因简历后续编辑而漂移；
- 问题覆盖项目深挖、技术决策、职责边界、成果和 JD 差距，且不泄露无关个人信息；
- 删除简历后不能开始新定向面试，历史面试仍可查看；
- 定向面试继续进入现有报告、能力画像和学习任务；
- 幂等提交、并发答案、恢复、归档、重答和删除全部回归通过。

## Public interface change

现有 `POST /api/interviews/start` 请求增加：

```text
resume_analysis_id?: string
```

现有响应保持兼容。面试列表和详情增加可选来源摘要：

```text
source_type: "general" | "resume"
source_resume?: { resume_id, analysis_id, display_name }
```

## Decisions and findings

- 定向面试创建后只使用不可变的最小上下文快照，后续简历编辑不会改变同一场面试。
- 快照排除姓名、联系方式和完整正文，并对联系方式模式做二次过滤。
- 简历删除不级联删除历史面试；历史显示“来源简历已删除”，但不会恢复原内容。
- 通用面试不传递新增上下文参数，原出题和评分路径保持兼容。
