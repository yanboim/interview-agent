# AI 面试教练产品需求文档

- 状态：当前产品基线
- 日期：2026-07-27
- 产品：Interview Agent
- 行为来源：[功能契约](../product-specs/feature-contract.json)

## 1. 背景与目标

产品为技术岗位求职者提供账号级、可持续的面试训练。核心目标是把岗位准备、知识
问答、模拟面试、能力画像和复习任务连接起来，并让每次训练结果可以持久化、恢复、
追踪和安全隔离。

## 2. 范围

### 当前范围

- 产品用户注册、登录、令牌刷新、退出、改密和恢复码；
- 目标岗位、方向、JD、提醒偏好和今日训练建议；
- 带会话历史、私人知识来源和可选公开搜索来源的AI问答；
- 可开始、逐题作答、评分、重答、恢复、归档和删除的模拟面试；
- 跨场次能力画像、趋势、薄弱点和准备度；
- 学习任务生成、状态管理和间隔复习；
- 独立管理员登录、用户角色、审计、产品事件和知识库管理；
- 版本化知识发布、回滚、后台任务、健康检查、指标和追踪。

### 不在当前范围

- 组织、团队或企业多租户管理；
- 真实招聘流程、面试排期和录用决策；
- 付费、订阅或账单；
- 原生移动应用；
- 人工面试官实时加入或音视频面试。

## 3. 角色

| 角色 | 目标 | 权限边界 |
|---|---|---|
| 产品用户 | 完成训练、查看个人数据和管理个人任务 | 只能访问服务端解析身份下的资源 |
| 管理员 | 管理用户角色、知识文件、发布任务和运行信息 | 使用独立登录面和管理员接口 |
| 运维人员 | 部署、监控、备份、恢复和事故处理 | 通过部署平台和受控运维入口操作 |
| 外部模型/搜索提供方 | 按配置处理请求 | 只接收完成该请求所必需且已获准的数据 |

## 4. 核心用户故事

### 账号与目标

- 用户能够注册并登录，刷新令牌后旧刷新令牌不可再次使用。
- 用户能够设置目标岗位、训练方向和JD，并在后续登录继续使用。
- 用户能够修改密码或使用一次性恢复码重置密码。

### 今日训练

- 用户打开工作区时能够看到基于目标、未完成面试、到期任务和薄弱点生成的建议。
- 用户能够从建议直接进入问答、面试或复习。

### AI问答

- 用户能够发送问题并接收流式回答。
- 当私人知识库实际参与回答时，界面展示来源。
- 同一内容的安全重试不重复形成正式历史或重复调用已完成结果。
- 同一会话生成中不允许第二个并发生成破坏消息顺序。

### 模拟面试

- 用户选择主题、难度和题数后开始面试。
- 每题回答会从技术准确性、原理深度、表达结构和工程实践评分。
- 网络失败后使用同一幂等键重试，不重复评分或生成下一题。
- 用户能够恢复未完成面试、查看历史、重答、归档或删除。

### 能力与学习

- 用户能够查看跨场次综合分、维度分、趋势、主题表现和薄弱点。
- 系统能够把薄弱维度和高频问题转为去重的学习任务。
- 复习后更新复习次数并按递增间隔安排下一次复习。

### 管理

- 普通用户不能登录管理员界面或调用管理员接口。
- 管理员能够管理安全文件名下的知识文件并发起异步导入。
- 新知识版本通过验证前不能替换服务中的版本；管理员可回滚到受管理版本。

## 5. 关键业务规则

- 服务端认证身份覆盖请求体中的任何用户标识。
- 产品账号和管理员账号使用独立登录入口与浏览器会话。
- 聊天和首次面试答案提交要求 `Idempotency-Key`。
- 同一幂等键与不同内容组合使用必须拒绝。
- 模型调用不处于数据库事务内；最终业务结果以条件提交和所有者令牌保护。
- 私人知识默认不发送到公开搜索；LLM重排默认关闭。
- 数据库结构通过Alembic演进，生产启动前完成迁移。

## 6. 页面范围

- `/today`：今日训练和目标引导；
- `/chat/{sessionId?}`：知识问答；
- `/interviews/{interviewId?}`：面试列表、进行态和报告入口；
- `/profile`：能力画像；
- `/learning`：学习和复习任务；
- `/history`：会话历史管理；
- `/admin`：独立管理员工作台。

页面和交互细节见[原型说明](../ux/PROTOTYPE-SPEC.md)。

## 7. 验收

每项已经交付的行为必须满足：

1. 在功能契约中为 `passing`；
2. 至少有一个实际执行该行为的验证引用；
3. 权限负向场景和失败恢复场景得到覆盖；
4. 相关原型、架构、运行或安全文档同步更新；
5. 适用的质量门禁通过。

验收矩阵见[验收测试](../quality/ACCEPTANCE-TESTS.md)。

## 8. 风险

- 模型输出存在不准确、偏差或格式异常；
- 私人知识和用户回答可能被发送到外部模型提供方；
- 评分容易被误解为招聘结论；
- 外部服务失败可能影响训练连续性；
- 模型、向量库和历史数据增长带来成本与容量压力。

风险通过来源展示、数据流开关、错误映射、可靠性状态、评估集、预算和运维门禁
控制，但不能被完全消除。
